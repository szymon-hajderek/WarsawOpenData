Event bus-delay dla UI

Jak pokazać użytkownikowi, ile spóźnia się autobus lub tramwaj, którym jedzie. Dane już płyną do przeglądarki, brakuje tylko widoku.

stan na 18.10.2026gałąź mainkontrakt API data/API.md

W skrócie

  1. Po kliknięciu „Jadę tą linią” aplikacja sama co 10 s pyta serwer o opóźnienie tego pojazdu. Nic nie musisz uruchamiać.
  2. Po każdej odpowiedzi na window leci event bus-delay z obiektem BusDelayDetail w event.detail.
  3. Twój komponent nasłuchuje tego eventu i pokazuje opóźnienie przy następnym przystanku (nextStop).
  4. Gdy available jest false, pokaż „Dane o opóźnieniu niedostępne”.

  • Start: confirm() w src/hooks/useVehicleDetection.ts ustawia delayVehicleId na id wybranego pojazdu, a efekt w tym samym hooku woła watchDelay(id). Pierwszy event przychodzi od razu, kolejne co 10 s.
  • Stop: nowa detekcja (requestLinePopup(), „Wykryj ponownie”, przycisk autobusu na mapie) albo „Nie jadę komunikacją”. Wybranie innego pojazdu i ponowne „Jadę tą linią” przełącza nasłuch na nowy pojazd.
  • Eventy lecą dalej, gdy użytkownik przejdzie do listy tras albo szczegółów trasy (okno pojazdu jest wtedy ukryte). To celowe: można pokazać opóźnienie także tam.

Co jest w event.detail

Typy: BusDelayDetail i DelayStop w src/types.ts. To dokładnie odpowiedź GET /api/live/delay z data/API.md, plus dwa powody błędu dodawane w przeglądarce.

poletypznaczenie
vehicleIdstringid pojazdu, np. bus-5914, tram-3120; to samo co VehicleCandidate.id
line, brigade, mode, vehiclestring?linia, brygada, bus / tram, numer taborowy; brak, gdy serwer nie odpowiedział
headsignstring | nullkierunek dopasowanego kursu, np. „Ursus-Niedźwiadek”
availablebooleanfalse = „Dane o opóźnieniu niedostępne”
delaySecnumber | nullopóźnienie w sekundach; ujemne = przed czasem; null, gdy niedostępne
reasonstring | nullnull, gdy dostępne; inaczej powód (tabela niżej)
nextStopDelayStop | nullprzystanek K, tu pokazujesz opóźnienie: name, scheduled, expected (= planowo + opóźnienie)
prevStopDelayStop | nullprzystanek K-1, na którym opóźnienie zmierzono: name, scheduled, passedAt
updatedAtnumber | nullczas ostatniego pobrania pozycji przez serwer (Unix, sekundy)
tripId, radiusMtechniczne, do debugowania

Godziny (scheduled, expected, passedAt) to napisy "HH:MM:SS" czasu warszawskiego, bez daty. Pokazuj je bez sekund, np. s.slice(0, 5).

Progi i kolory to propozycja. W raporcie z symulacji „punktualnie” to ±60 s, czerwony od +1 min, zielony od −1 min. Kolory w aplikacji bierz z palety (src/map/palette.ts, motyw MUI).

Gotowy hook do skopiowania

Nasłuchuje eventu i zwraca ostatnią odpowiedź. Komponent dostaje null, dopóki nic nie przyszło (pojazd nie potwierdzony).

src/hooks/useBusDelay.ts
import { useEffect, useState } from 'react';
import { BUS_DELAY_EVENT } from '../api/delay';
import type { BusDelayDetail } from '../types';

/** The latest `bus-delay` answer for the confirmed vehicle, or null before the first one. */
export function useBusDelay(): BusDelayDetail | null {
  const [delay, setDelay] = useState<BusDelayDetail | null>(null);
  useEffect(() => {
    const onDelay = (e: Event) => setDelay((e as CustomEvent<BusDelayDetail>).detail);
    window.addEventListener(BUS_DELAY_EVENT, onDelay);
    return () => window.removeEventListener(BUS_DELAY_EVENT, onDelay);
  }, []);
  return delay;
}

/** "+3 min", "punktualnie", "1 min przed czasem"; null when there is no delay to show. */
export function delayLabel(d: BusDelayDetail | null, onTimeSec = 60): string | null {
  if (!d || !d.available || d.delaySec == null) return null;
  const min = Math.round(Math.abs(d.delaySec) / 60);
  if (Math.abs(d.delaySec) < onTimeSec) return 'punktualnie';
  return d.delaySec > 0 ? `+${min} min` : `${min} min przed czasem`;
}
użycie w komponencie
const delay = useBusDelay();
const label = delayLabel(delay);

if (delay && vehicle.confirmed?.id === delay.vehicleId) {
  return label
    ? <Chip label={`${label} · ${delay.nextStop?.name} ${delay.nextStop?.expected?.slice(0, 5)}`} />
    : <Typography color="text.secondary">Dane o opóźnieniu niedostępne</Typography>;
}

Sprawdzaj delay.vehicleId === confirmed.id: po zmianie pojazdu może jeszcze dojść ostatni event poprzedniego. Stan ze starego pojazdu wyczyść przy nowej detekcji (po BUS_POPUP_REQUEST_EVENT eventy przestają lecieć, ale hook pamięta ostatni).

Jak to testować

Zmień delaySec na -75 (przed czasem) albo ustaw available: false, reason: 'no_pass_in_radius', delaySec: null, żeby zobaczyć pozostałe stany. Bez serwera aplikacja sama wysyła eventy z backend_unavailable co 10 s, więc sztuczny event nadpisze je tylko na chwilę.

Z prawdziwym serwerem

  1. cd backend && uv run uvicorn main:app (potrzebny PORTAL_KEY w .env) i cd frontend && npm run dev.
  2. Serwer potrzebuje kilku minut, żeby zebrać pozycje: tuż po starcie odpowiedzi to 503 albo no_pass_in_radius.
  3. W przeglądarce nie ma lokalizacji, więc wykryte pojazdy to te najbliżej wpisanego startu. Wybierz dowolny z listy i kliknij „Jadę tą linią”.
  4. Odpowiedź serwera możesz sprawdzić ręcznie: curl "localhost:8000/api/live/delay?vehicle=bus-5914" (id z okna pojazdu).

Na co uważać

  • Opóźnienie dotyczy przystanku, który pojazd właśnie minął (K-1), a pokazujemy je jako prognozę dla następnego (K). Dlatego w UI mów „przy przystanku Centrum: +3 min”, a nie „autobus jest 3 min za”.
  • Wartość zmienia się skokowo, gdy pojazd minie kolejny przystanek, czyli co 1–3 minuty. Między przystankami kolejne eventy mają ten sam wynik.
  • Dokładność na nagraniu z 17.10 (6 linii, 1130 przejazdów): opóźnienie dostępne w 98% przypadków, połowa wyników różni się od wzorca o 2 s lub mniej, 90% o 14 s lub mniej. Raport: artifacts/delay-simulation.html.
  • Działa dla autobusów i tramwajów. Metro, SKM i pociągi nie mają tych danych na żywo.
  • Eventy są tylko dla pojazdu potwierdzonego „Jadę tą linią”. Kandydaci w oknie wyboru nie mają opóźnień.

Do poprawy w src/api/delay.ts przed użyciem na produkcji

  • fetchDelay woła względny adres /api/live/delay zamiast apiUrl('/api/live/delay') z src/config.ts. Działa przez proxy Vite, ale ignoruje VITE_API_URL i nie przełącza się na tryb przykładowy przy pustym API_URL, jak pozostałe wywołania.
  • Odpowiedź nie przechodzi przez src/api/validate.ts, więc zły kształt danych nie jest traktowany jak „serwer niedostępny”.

Oba punkty poprawia PR #88 (otwarty w chwili pisania). Po jego scaleniu ta sekcja jest nieaktualna.
