# Changes on `feature/speed-history`

- New backend part that counts the user's trip history: `algorithms/speed_history.py` (`split_track`, `summarize`, with tests) and the endpoints `POST /api/history/records` (GPS track + planned legs -> per-mode records without coordinates) and `POST /api/history/summary` (records -> average speed per mode). Stateless: nothing is stored or logged on the server. Tests in `backend/tests/test_history_api.py`.
- Route view: "Rozpocznij przejazd" / "Zakończ" records the ride with GPS (memory only, screen kept on where supported) and saves the result; a small banner shows a running recording on the other screens; errors can be retried.
- The device keeps only the derived records (distance, moving time, speed, date) in localStorage (`trip-history`, max 200); "Wyczyść historię przejazdów" on the Preferences page removes them.
- Preferences: each of Pieszo, Rower and Wózek shows "Twoja średnia z historii" (needs 5 trips), a suggestion "Użyj X km/h" when it differs by 10% or more from the current speed, and a switch "Zawsze używaj średniej z historii" (`autoSpeed`). When on and there are enough trips, the average replaces the level / typed speed everywhere (route list summary, filters) and the level selector is locked with an explanation.
- Assumptions: the moving distance of the track is shared between the route's legs in proportion to their planned distance (the track must be 0.5x-2x of the plan, otherwise nothing is saved); standing still and GPS gaps are not counted; walking legs count as wheelchair when a wheelchair type is set; only walking, cycling and wheelchair have a history (public transport speeds are not user-adjustable); browsers cannot record in the background, so the screen has to stay on.
- `AGENTS.md` updated. No new dependencies.
